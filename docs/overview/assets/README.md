## Why the old PNG is still here

`grant-pathway-process-overview.png` was generated by an image model and cannot be edited — its text is pixels. That is how it came to carry **"(User confirms accuracy, the funder funders accuracy..)"** through several versions of a document intended for external distribution, along with a dangling "AI", two unfinished ellipses, a "Free for small UK charities" line that contradicted the document's own audience definition, an imitation of the Microsoft Word logo, and no depiction of the eligibility hard stop. It is kept only because the live overview (v1.18) still references it; delete it when the Word file is rebuilt against `-v2.png`.

The lesson worth keeping: **do not use generated raster artwork for anything containing text that has to be correct.** Nobody proof-reads an image.

## Re-exporting the PNG after editing the SVG

There is no `rsvg-convert` or Inkscape on this machine, and ImageMagick's SVG delegate renders text poorly. Headless Chrome is the reliable route, but it will not write a screenshot from a `file://` URL, so serve the folder first:

```bash
python -m http.server 8931
```

Then, from PowerShell (adjust the output path):

```
& "C:\Program Files\Google\Chrome\Application\chrome.exe" --headless=new --disable-gpu --no-sandbox --hide-scrollbars --user-data-dir=%TEMP%\chromeprofile --force-device-scale-factor=2 --window-size=1600,830 "--screenshot=grant-pathway-process-overview-v2.png" "http://localhost:8931/grant-pathway-process-overview.svg"
```

`--force-device-scale-factor=2` is what produces the 3200 × 1660 output; the SVG's own viewBox is 1600 × 830. A `--user-data-dir` is required — without it Chrome fails silently with exit code 0 and writes nothing.

## Editing the SVG

Plain XML, commented, using the `BR-02` palette from `docs/app-name-and-branding.md`. Two things to know:

- **SVG has no text wrapping.** Each line of body copy is its own `<tspan>` with an explicit `dy`. If you lengthen a line, re-break it by hand and check the render — text will happily overflow its card.
- **XML comments cannot contain `--`.** Separator lines use `=` for that reason.
