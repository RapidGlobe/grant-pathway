# Question-Coverage Analysis — feeding the BD-03 / BD-04 open decision

**Tier:** 2 — Check if relevant
**Volatility:** High — actively being extended, funder by funder
**Update when:** A new funder is tested against this framework, or a design decision is made that resolves part of the open question below

---

## 1. Purpose

`BRD-Grant-Pathway-v0.5.md` Section 10 records BD-03 ("non-narrative questions are pre-filled from profile where possible; shown as reminders otherwise") as **never built**, and flags it as an open decision rather than a resolved gap — see the BD-03 note in that document.

This document is the working analysis behind resolving that open decision properly, rather than funder-by-funder. It is not itself a decision record. It exists so the reasoning survives past this session and the next funder test doesn't have to rediscover it from scratch.

## 2. How this started

A review of BD-03 raised a bigger concern: were we making scope decisions (BD-03, BD-04, BD-07, BD-08, and ad hoc calls made during funder testing) piecemeal, without reference to a shared objective — risking a product that doesn't hold together once it's in real use?

That led to stepping back from implementation questions entirely and re-examining the objective for Grant Pathway. Two candidate framings were tested and rejected:

- **"Narrow (writing-only) vs. broad (any guideline/form, we handle it)"** — too abstract to make concrete calls from.
- **"Structured vs. narrative funders"** — disproven by evidence (see Idlewild, below): a single, maximally "structured" form (Idlewild Arts) turned out to be 75% non-narrative and 25% narrative fields, mixed within itself. Structured/narrative was never a stable property of a funder or even a document — this is also what BD-08 already found and retired the funder-level badge for.

The question that replaced both: **"How do we make sure every question in any form gets covered — narrative or not?"** Everything below is testing whether that question, and a candidate design for answering it, survives contact with real funder guidance.

## 3. The candidate design tested (for reference)

Before testing against more funders, a tiered field-handling model was proposed for Idlewild specifically ("Option D" in the session this document is drawn from):

1. Identity/contact fields auto-fill from the charity profile (near-zero ambiguity — org name, address, charity number, etc.)
2. Financial/budget fields get guided structured entry (extending the existing `is_budget_question` amber-card pattern)
3. A reusable "org bio" narrative, written once and reused/edited per application, rather than rewritten from scratch each time
4. Eligibility gates, picklists, and file uploads become simple reminders/checklists
5. Project-specific narrative questions keep the existing AI-assisted writing treatment, unchanged

This held up reasonably well for Idlewild. It has not held up since.

## 5. Cross-cutting patterns

- **Non-narrative fields are not one bucket.** Evidence so far spans at least six distinct kinds of "not narrative," each needing different handling: trivially profile-pre-fillable (name, address); structurally novel (branching/conditional); inherently one-off (a specific meeting's minutes); sensitive/consent-gated (DEI data); purely mechanical and checkable (budget arithmetic); and fuzzy/judgement-based (percentage spend caps with case-by-case exceptions).
- **A "form" is not always one static list of questions.** It can branch by an earlier answer (Clothworkers' project type), by the applicant's own history or self-assessed status (Stony Stratford), or exist as multiple sequential stages reviewed months apart (Clothworkers Large Grants).
- **"Guidance" is not always a form at all.** It can be a scoring rubric to write _toward_ (Clothworkers' Impact Framework), or spend rules to validate a budget _against_ (Henry Smith), arriving as a document entirely separate from the application form itself.
- **The output Grant Pathway hands back is not always a generic artifact the charity retypes elsewhere.** Sometimes the real submission has to be the funder's own native document, signed by specific named people in specific roles (Stony Stratford).
- **Guidance "rules" span a spectrum from unautomatable to trivially automatable**, and treating them uniformly is a mistake in either direction — from Henry Smith's judgement-based 25%/40% staff-cost cap to Stony Stratford's purely arithmetic "figures must add up or automatic ineligibility."

## 6. What this means for BD-03

BD-03 as originally written ("pre-fill non-narrative questions from profile where possible; shown as reminders otherwise") assumed a flat list of fields inside one static form. None of the four funders reviewed so far actually look like that. BD-03 is not wrong so much as too small a fix for what has actually been found — resolving it in isolation, without accounting for branching forms, scoring-rubric-driven coaching, native-document output, and the sensitivity/automatability spectrum above, would very likely need to be redone once the next funder surfaces one of these problems again (as Clothworkers already did once, via `IT-CW-08` / `GAP-28`).

## 7. Status

No design has been agreed. This is discovery, not decision-making. The north-star question from Section 2 still stands; the job now is to keep testing it against funders until it stops breaking, then design against the full set of findings rather than the first one.
