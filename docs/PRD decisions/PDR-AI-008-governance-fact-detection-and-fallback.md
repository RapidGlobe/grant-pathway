# PDR-AI-008 — Governance/Reserves Fact Detection and Fallback

## Question

When should the app ask a charity about one of the 5 governance/reserves facts (total annual expenditure, reserves, trustee-relatedness, bank-signatory count, bank-signatories-relatedness), and what happens when a funder's guidelines don't clearly and precisely raise one of them? Should the user ever be asked to judge relevance themselves?

## Context

Earlier the same day (2026-07-15, commit `82e11d9`), these 5 facts were re-sited from `charity_profiles` into the `application_items` item-graph as a fixed group, always shown unconditionally on every application regardless of funder (see `ADR-DATA-006`'s matching amendment). WJ live-tested this and found the block felt disjointed from the rest of Step 4: every AI-extracted question carries a "Page N of the guidelines" citation and funder-specific guidance, but the 5 fixed items had neither, and were shown even for funders that never ask about any of them.

This reopened the "placement only, no relevance detection" scope decision made earlier that same day. The discussion converged on folding these 5 facts into the same guideline-driven extraction pipeline that produces ordinary narrative questions — citation-backed, shown only when the guidelines actually raise the topic — rather than a separately-coded always-on block.

The open question was what to do when the guidelines raise a topic only vaguely, or not at all. `docs/user-personas-journeys-and-use-cases.md`'s Persona 1, Margaret, is explicit that she has no formal fundraising training, finds funder language confusing, and is "unsure whether her answers are actually addressing what the funder is asking." Any mechanism that asks the user to judge whether a given fact is relevant hands her exactly the kind of call her persona says she can't reliably make.

## Options

- **Option A — Strict citation gate only:** Extract a governance fact only when the AI finds a precise, verbatim-quotable citation (a specific sentence, page-anchored, matching the citation discipline already used for narrative questions). Anything less precise is dropped entirely; a manual "add a financial or governance detail" picker (scoped to the 5 known facts) is offered to everyone as the sole fallback. Simplest to build, most consistent with existing citation rules, but risks under-asking whenever a requirement is real but not phrased as one crisp quotable line — and leaves the fallback dependent on the user recognising a gap exists.
- **Option B — Relaxed-citation middle tier:** Add a second tier between "precise quote" and "nothing": allow a citation with just a page/heading pointer and no exact quote, for cases that are clearly implied but not cleanly localised to one quotable sentence. Manual-add remains the fallback only for the residual fully-uncited case. Considered and set aside in favour of Option C's simpler two-tier shape (see Rationale).
- **Option C (decided) — Auto-show on any signal; manual-add as a rare experienced-user shortcut only:** Show a governance fact automatically whenever the AI has _any_ signal at all that the guidelines raise it — even an imprecise, unlocalised one — so the user is never shown a gap they're expected to notice and fill themselves. Manual-add (a short, plain-English-explained picker of the 5 facts) stays available to everyone, but is reserved for the rare case where the AI found no signal whatsoever and a more experienced user (e.g. Persona 2, David) independently knows a funder-specific quirk the guidelines don't spell out. The system never proactively suggests a governance fact to a novice user when it has no signal — that was explicitly considered and rejected (see Rationale).

## Decision

**Option C.** Auto-include a governance fact whenever the AI detects any signal for it, regardless of citation precision. Manual-add is kept as a secondary, always-available but rarely-needed affordance, explicitly not framed as something a novice user is expected to use to plug a gap the AI left. The system does not proactively prompt a user toward adding a fact it has no signal for.

## Rationale

- A picker that asks "tick whichever of these you think applies" (Option A's sole fallback) assumes the user can judge funder-specific relevance — precisely the judgement Margaret's persona says she doesn't have. Making that the primary safety net would relocate the guesswork from "read the funder's PDF" to "read this shorter list," not remove it.
- Being proactive toward novice users when the AI has no signal at all (e.g. "I noticed this funder discusses financial resilience — want to answer a question about reserves?") was considered and explicitly rejected: WJ's judgement was that this could make things worse for Margaret by introducing a decision point instead of removing one, not better.
- Option B's relaxed-citation tier was set aside once Option C's simpler two-tier shape (show on any signal / manual-add only for zero signal) covered the same ground without needing a separate citation-precision distinction — the practical effect is the same protection for a novice user, with one fewer tier to build and reason about.
- Manual-add is not persona-gated (removing it for novices would be arbitrary), but is designed and expected to be used mainly by returning, more experienced users — plain-English explanations on each option are required precisely because a novice user could still land on it.
- This deliberately trades a small amount of citation precision (auto-shown items may only have a vague signal behind them, not a clean quote) for not silently dropping a fact a novice user has no way to notice is missing.

## Status note

**Built (2026-07-15, same day as the decision).** Supersedes the "always show all 5 governance items unconditionally" placement built earlier the same day (commit `82e11d9` — see `ADR-DATA-006`'s 2026-07-15 amendments, both the original and the follow-on, and `data-model.md` §4c). A new `"governanceFacts"` extraction category (`lib/prompts.ts`, Zod-validated in `route.ts`, citation-reconciled the same way as questions/sections) now drives whether each of the 5 fixed items is created at all — `lib/governance-items.ts`'s `resolveGovernanceInserts()` builds the upsert payload only for facts actually detected, and `isOrphanedItem()`'s governance-specific carve-out was removed since a detected item is now genuinely part of the AI's own sync cycle. The dedicated "Governance and reserves" Step 4 heading was removed — a detected item renders as an ordinary card.

**Manual-add fallback also now built (2026-07-15, same day, fast-follow).** A quiet link at the bottom of the Q&A list — "Need to add something about your finances or governance that wasn't asked above? Add it." — appears only when at least one of the 5 facts isn't already shown; it is never shown once all 5 are present, and never proactively surfaced (matching the Decision above). Clicking it reveals checkboxes for just the missing facts, each with a plain-English explanation (`GOVERNANCE_FIELD_EXPLANATIONS`, `lib/governance-items.ts`) rather than a bare jargon label. A new `application_items.added_manually` boolean column (migration `20260715000001`) distinguishes a manually-added item from an AI-detected one with no citation — both otherwise look identical — driving an honest "Added by you" badge in place of a citation badge. New server action `addManualGovernanceItems` (`actions/applications.ts`), scoped to the closed 5-field vocabulary only (never free text). `tsc --noEmit`, `eslint --max-warnings 0`, all 64 tests pass (4 new). Migration applied to `grant-pathway-dev` only, confirmed via `supabase migration list` (24/24 matched) and `supabase projects list` (`grant-pathway-prod` remains unlinked).
