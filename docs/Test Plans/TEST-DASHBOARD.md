## Why this dashboard was reset (read before testing)

On 2026-07-01, a full infrastructure audit found that `grant-pathway-dev` and `grant-pathway-prod` had been silently missing critical schema for weeks:

- `reserve_ai_slot`, `update_ai_slot_token_count`, `cancel_ai_slot` (the AI usage-cap RPCs) were missing from **both** projects. Every AI route calls `reserve_ai_slot` before touching Bedrock, so **AI features have been non-functional on every hosted environment** since this mechanism was introduced into the route code on 2026-06-22 — only local Docker development had the full schema.
- `approve_application` and `reopen_application` were missing from **production only**, introduced 2026-06-29. Step 5 "Approve" and the dashboard "Reopen" action were broken in production.

This has now been fixed and verified on both projects (full detail: `docs/Implementation Plan/CHANGELOG.md`, 2026-07-01 entries). But it means **every test result recorded in the previous dashboard (archived at `docs/Test Plans/archive/TEST-DASHBOARD-v1.39.md`) predates the fix** — all funder testing finished by 2026-06-17, five days before the AI-cap RPC even existed in the code. None of those 🟢 results are evidence that the _current_ codebase works end-to-end.

**Before trusting any result below, or any result you're about to record:** run RT-00 in `regression-test-plan.md` first. It takes two minutes and confirms the environment you're testing actually has the schema it needs.

## Funder Readiness Standard

This defines what "done" means for a funder at each status level, and what is acceptable to have live in the dropdown at each stage.

### 🟢 Fully tested — supported

All of the following must be true:

- **RT-00 (environment/schema check) passed on the same environment used for this funder's testing**
- Full funder test plan exists covering every step from login to Word export (minimum 10 test cases per AGENTS.md)
- All tests passed with no unresolved defects (severity: blocking or high)
- AI summary time recorded and within NFR-01 (≤45 seconds)
- Any funder-specific eligibility, question, or format behaviour verified in context
- Funder has been confirmed open and accepting applications at time of testing

### 🔁 Needs re-verification

A funder that previously met the 🟢 bar, but whose test results predate a confirmed infrastructure gap (see above) and have not yet been re-run against the current, fixed schema. Treat as untested for planning purposes until re-verified — do not assume it still passes.

### 🟡 In dropdown — not fully tested

A funder may be live in the dropdown before full testing is complete. This is an accepted risk during Phase 5, subject to the following conditions:

- The funder has been added to the dropdown with correct `funder_type` and `grant_range` metadata
- A test plan exists or is in progress, OR the funder is parked (programme closed)
- Users may encounter untested behaviour — this is acceptable during the controlled P5 pilot period where users are known to Rapidglobe
- Any defect reported by a pilot user is treated as P1 and resolved before broader rollout

**Review point:** Before public launch (post-P5), every funder in the dropdown must be at 🟢 or removed. 🟡 and 🔁 funders should not be accessible to anonymous signups at launch.

### ⏸️ Parked — programme closed

Funder is in the codebase but the grant programme is currently closed or inactive. The funder remains in the dropdown (marked **inactive in the database**) so that existing applications are not broken. No testing required until the programme reopens. **This rule is now correctly enforced on dev for all 4 previously-affected funders (see Known Issues above) — prod fix still outstanding.**
