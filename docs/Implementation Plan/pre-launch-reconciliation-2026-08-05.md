**Method.** Per the task's own instruction, this was run as a **sweep, not a read-through**: where a divergence was found, the whole live documentation set was grepped for the same fact and every instance recorded, not just the one noticed. Where a sweep was deliberately bounded, the row says so.

**Gate position.** The Phase 4 → Phase 5 gate is signed off (WJ, 2026-06-17), so `AGENTS.md` §2's phase-boundary ADR sweep is nominally discharged. ### The recurring shape of these findings

Worth stating once rather than per row. Of the 23, **seven are a document failing to say where it stands** (R-01, R-02, R-03, R-04, R-20, R-23, and R-17's ✅-means-inert) and **three are a correction that was made once and never swept** (R-10 most starkly, R-18, R-08). That is the same split the July 2026 audit produced, and it is the argument for `P5.0` existing at all: the documents are not sloppy, and nothing was checking.

**R-10 deserves the emphasis, and the sweep made it worse than first written.** The 320px-vs-1024px conflict was recorded **twice** before today, with **contradictory resolutions**: the retired plan's **OI-07** said "ADR takes precedence… mobile is post-v1. No action required", while the live plan's own discrepancy row **D24** logged the same conflict and reconciled it the other way — "must be usable on mobile browsers per C16 and NFR-05 (minimum 320px)", overriding the ADR it cited. So the initial framing here ("the class fix already existed in writing and never propagated") was only half right. **The truth is sharper: it was noticed twice and settled inconsistently, and the live record was the wrong one** — which is why eight live documents still promised mobile support this morning. A conflict resolved in two directions is worse than one never resolved, because each record makes the other look redundant.
