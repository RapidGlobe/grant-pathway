# Grant Pathway — ADR Consequences Traceability

**Tier:** 2 — Check if relevant to the task
**Volatility:** Medium
**Update when:** A GAP item is resolved or a phase gate is passed

**Purpose:** Maps every ADR consequence to a specific implementation task. A gap in this table means a consequence has no covering task — it will not be implemented unless a task is added. This is the single place to see whether the full spec is covered.

## Status symbols — read this before trusting any row

**Added 2026-07-30 (Phase 5 restructure item C2, approved by WJ).** Until today a single ✅ in this table meant **two different things**, and a signed phase gate depended on the difference.

| Symbol       | Meaning                                                                                                                                                         | Do not read it as                                       |
| ------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------- |
| ✅           | **Built.** The code, configuration or artefact exists. The ADR consequence is genuinely discharged.                                                             | —                                                       |
| 📋           | **Tasked only — NOT built.** A step exists in `IMPLEMENTATION-PLAN.md` and nothing more. The consequence is **not** discharged and the code does **not** exist. | Do not read as done. This is a promise, not an outcome. |
| ➖           | **Accepted deviation.** Consciously not doing it, with the decision and residual risk recorded in the row.                                                      | —                                                       |
| ⚠️           | **Gap.** No covering task at all.                                                                                                                               | —                                                       |
| 🔵 / Partial | Some parts built, others tasked or deferred. The row says which.                                                                                                | —                                                       |

**Why this exists.** GAP-24's status read `✅ 2026-06-16 — disclaimer wording fix step added to P5.3`, meaning _a task was written_. Two rows away, GAP-26's `✅ Resolved 2026-06-15 (commit 372d95b)` meant _the code exists_. Same column, same symbol, opposite claims. The consequence was not theoretical: the **Phase 4 → Phase 5 gate sign-off** (2026-05-22, signed WJ 2026-06-17) reads "GAP-05/12/17/21/22/23/24/25/26 resolved" — a statement that was true as written and false as read. See the annotation on that gate row.

**Sixteen rows were reclassified from ✅ to 📋 on 2026-07-30** — ten in the Gaps register (GAP-03, 05, 12, 17, 21, 22, 23, 25, 28, 31) and six in the ADR consequence tables (ADR-ARCH-002, ADR-ARCH-003, ADR-ARCH-005, ADR-OPS-005, ADR-SEC-002, ADR-SEC-003). **The ADR-table half matters more than the register half:** those are the rows a future session reads when performing the mandatory ADR-consequences check in `AGENTS.md` §2, so a ✅ there would have told it the consequence was discharged when the code did not exist.

**How to use:**

- Before starting any phase, scan for ⚠️ Gap **and 📋 rows**. Every gap must be resolved (task added or N/A justified) before phase work begins, and every 📋 is unbuilt work still owed.
- When a new task is added to cover a gap, update the Task column and set the status to **📋** — not ✅.
- **When the code actually lands, change 📋 → ✅ and say what was built.** This is the step that was missing, and it is why a tick came to mean two things.
- Task-level progress still lives in `IMPLEMENTATION-STATUS.md`; this table records whether the ADR consequence itself is discharged.
