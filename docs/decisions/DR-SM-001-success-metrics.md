# DR-SM-001 — How Success Will Be Measured

## Question

How will success be measured for the app?

## Context

Without defined success metrics, it is impossible to know whether the app is delivering value or needs to change direction. Metrics should reflect the app's core purpose — easing the grant application burden for charities — rather than vanity metrics like sign-up counts. Meaningful metrics might include time saved per application, number of applications submitted, application success rate, or charity retention. Some metrics are easy to measure (usage counts) while others require data charities may not share (application outcomes). Deciding this early ensures the right data is collected from day one.

## Options

- **Option A: Usage metrics** — Measure sign-ups, active users, applications created, and sessions (easy to collect; limited insight into real impact)
- **Option B: Time saved** — Measure how long application tasks take with and without the app (requires user surveys or time-tracking)
- **Option C: Application success rate** — Track whether applications made using the app result in funding awarded (requires charities to report outcomes)
- **Option D: Charity satisfaction score** — Regular NPS or CSAT surveys to charities using the app
- **Option E: Combination** — Track usage metrics as a baseline plus one qualitative outcome measure (e.g. satisfaction score)

## Decision

**Partial decision — minimal passive metrics in v1; formal framework deferred.** The app will capture basic usage counts as a by-product of the database (registered charities, applications created, returning users). No analytics platform, dashboard, or survey infrastructure will be built for v1. A satisfaction survey and formal impact reporting framework are deferred to a later phase, to be revisited when the CIC is established and operational grant funding is being sought.

## Rationale

A full metrics framework is overkill for v1. However, basic database counts require no extra tooling and provide an invaluable baseline for demonstrating impact to future grant funders — data that cannot be collected retroactively. Deferring everything would risk having no evidence of impact when the CIC applies for operational funding. The satisfaction survey and formal reporting are deferred until there is a meaningful user base and a CIC structure in place to use that data purposefully.
